独立Python功能入口：不需要命令行参数

终端第一次运行：
cd /home/aster/Desktop/Panthera-DualNXP-Integration
source /home/aster/miniforge3/bin/activate panthera

然后按需要选一个：
python 原臂遥操.py        原臂＋原手，GELLO接原臂NXP J11
python 新臂遥操.py        新臂＋新手，GELLO仍接原臂NXP J11
python 双臂遥操.py        同一个GELLO控制双臂双手
python 原臂位置保持.py    原臂高增益保持启动时实测位置
python 新臂位置保持.py    新臂低阻抗保持启动时实测位置
python 原臂重力补偿.py    原臂纯重力补偿，可手动拖动，不保持位置
python 新臂重力补偿.py    新臂纯重力补偿，可手动拖动，不保持位置
python 原手滑条.py        原手五指滑条，同时运行原臂重力补偿
python 新手滑条.py        新手五指滑条，同时运行新臂重力补偿
python 原臂状态.py        只查询原臂和原手反馈，默认30秒
python 新臂状态.py        只查询新臂和新手反馈，默认30秒
python 读取GELLO.py       只读NXP USB上的七个GELLO节点，默认30秒
python 查看回零状态.py    只观察两臂回零阶段，默认30秒
python 查看双板通信.py    只查询板间通信状态和计数，默认30秒

也可在IDE里选择panthera环境，直接运行对应Python文件；不要求IDE工作目录在项目根目录。
仅import这些入口不连接硬件；直接运行运动类入口会按既有流程接管相应机械臂。

参数在运行参数.py：IP、节点、端口、两侧Kp/Kd、软限位、手控制参数、持续时间。
TELEOP_CONFIG['boards']['right'] = 原臂node12；['left'] = 新臂node11。
遥操默认nxp-usb，所有遥操入口的GELLO都接原臂J11，微雪跳帽B档。
遥操持续时间TELEOP_SECONDS=0表示持续运行；读取类DIAGNOSTIC_SECONDS=30。
手滑条HAND_MODE=3、HAND_CURRENT_MA=500、HAND_FRICTION_SCALE=0，运行时也控制该侧臂的补偿。
固定GELLO零点与动力学模型继续引用已有标定文件，不重新标零。
旧的带参数run-one-gello-two-arms.py入口继续读取原JSON；独立中文入口用运行参数.py中的值。

同一侧不要同时运行两个控制入口。当前程序退出行为沿用既有实现：
三个遥操入口接管后Ctrl+C、时间到期或软件异常，请求NXP持续柔顺保持（重力补偿＋阻尼＋低刚度），不会默认停驱动。
电脑目标超过50ms未更新也由NXP接管；位置保持、重力补偿、手滑条等共用Session入口正常退出也交给NXP保持。
该保持仍带电，不能当作断电状态；断电、CAN反馈丢失或电机故障时无法保证支撑，需要机械制动/支撑。
启动时先检查各手反馈和模式3；require_hands=False时，未就绪的手关闭本次控制和查询，机械臂继续启动。在线手照常跟随，跳过的手在本次运行中不自动重新接入；恢复手后重新运行程序即可。
运行中已接入的手若失去反馈，仍按原有流程停止。
两臂回零同时调度；一侧先到位会持续收到保持目标，等待另一侧完成。
现场急停仍是立即切断动作的方式。
回零依旧按任一NXP的SW2，触发两臂一起回零；查看回零状态.py不触发动作。
正常退出及本次烧录后为普通待机，再次运行程序即可接管，不必按SW2解锁。回零跟踪偏差/回零超时会停下轨迹并柔顺保持；真实的反馈/电机故障仍需排除原因后按SW2恢复；手未就绪不会阻止机械臂启动。

验证：14个入口均在项目外目录通过--help检查；新旧参数逐项离线比对一致；
既有单/双臂与独立调参共24项回归通过。本次未运行硬件、未烧录。

遥操软限位：超出边界的目标被截到边界，仅挡住该轴向外运动；目标返回范围内即可向内运动，无需重启。到限位、实测超速、跟随误差不再触发退出。当前reference_filter=False：恢复旧版直接位置跟随，不启用15度/秒、30度/秒²轨迹过滤；MIT速度目标沿用旧版0。目标在角度范围内当周期透传，超出范围截断，反向回到范围内立即跟随。

两臂均取消遥操跟随误差退出，历史配置中的tracking_error_deg、measured_velocity_deg_s、position_tolerance_deg只兼容读取、不参与退出。直接位置跟随不积累轨迹进度，也不因调度间隔重新拉慢目标。有效反馈、电机故障响应和回零阶段遇阻柔顺停止保留；增益及GELLO固定零点不变。此修改只涉及电脑程序，无需烧录。

手部上电通信修正：板端收到逐轴模式0确认后，停止待机/硬故障状态下的重复STOP，避免持续电机报文干扰手启动。电脑入口仍会先开启六轴只读查询取得新鲜反馈，再申请控制；确认记录不会跨越回零/保持/遥操沿用。两臂正常控制与柔顺保持方式不变。

重力补偿限位试验（独立入口，不替换原来的纯重力补偿）：
  python 原臂重力补偿限位.py
  python 新臂重力补偿限位.py
一次测试一侧，先退出占用端口的遥操/重力补偿程序。角度读运行参数.py，阻力读限位试验参数.py。
边界前最后3°按角度连续增强恢复力，最后6°渐入电机本地双向阻尼抑制回弹。
静止在边界时请求满额向内力矩，回弹时减力制动；启动仍渐入1秒，与到边界判断无关。
前馈及按反馈估算的六轴总力矩上限为[21,36,36,21,10,10] Nm（模型effort值）。
电机瞬时总输出受自身限制，主机估算上限不是硬件限幅；尚未实机验证消抖效果。
松手可能快速回弹，不能保证实际角度绝不越界；详见试验说明。
不启动回零轨迹、不操作灵巧手。Ctrl+C沿用板端柔顺保持。详见重力补偿限位试验说明.txt。
