实物 SDK 测试结果，2026-10-30
通路：PC Python SDK -> UDP/Wirelink -> FRDM-MCXN947 -> 共总线 CAN FD -> J6与手8。
J4显式失能：管理操作9，target_mask=8；返回status0，实物模式回读0。
本轮演示无手模式切换、无J4使能，机械臂运动掩码32（仅J6）。
手：拇指0.007 -> 0.450 -> 0.007rad，六路电机前馈[0,100,0,0,0,0]mA，独立控制前馈100mA。100mA不是限流。
J6：MIT模式21，目标从当前编码器位置+5度再返回，目标斜率1度/秒，kp=3Nm/rad、kd=0.08Nm*s/rad、tau_ff=0。12秒发送6000个MIT目标。
测得J6行程3.2739度，最终5.2954度，相比初始3.2959度仍差约2度；没有宣称精确跟踪或精确返回。未自行提高增益或反复追加运动。
其余5轴反馈位置本轮未变，模式均0；采样期间全部电机反馈最大时龄2.1ms。
最终六电机与手故障码全0，CAN发送失败0/坏帧0，UDP坏包0/旧包0/发送丢弃0。
控制周期均值2000us，最大2200us。本轮不是完整500Hz网络频率分位数基准。
演示完成后退出应用active并释放控制权；J6电机模式仍21，未发送J6失能，因此不能把退出程序称为电机已失能。
修正：手回包ID按实际数据使用0x108xx；柔顺帧补上独立控制前馈；分项读取代替0A00；按joint_mask筛选运动输出；CAN等待可用邮箱避免突发EAGAIN；Wirelink ACK的message_id必须0。
协议应用revision3，新增hand_control_feedforward_ma；本目录host与protocol必须配套。
J6按官方标准4438_30比例0.5256换算，只开放该轴模型转换；不是六轴标定完成，也未启用重力补偿。
默认运行demo_thumb_joint6.py只输出计划，--execute才会再次实物运动。不要在不需要重复运动时使用--execute。
历史第一次演示在手模式管理请求后超时，未进入J6运动。SDK ACK修复后本轮所有RPC成功；原始失败日志保留。
